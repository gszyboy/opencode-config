# 已有项目AI协作规范

## 核心原则

**保守优先**：宁可多问，不可乱改
**动态预算**：默认保守，可按需扩展
**红线必守**：数据库结构、认证鉴权、支付财务绝对不改

---

## 决策升级机制（已有项目专用）

### Level 1：评估模式（默认）
- **场景**：刚接手项目、不确定风险
- **AI权限**：只读、诊断、回答问题
- **改动限制**：不改任何代码

### Level 2：保守修改（需用户明确授权）
- **场景**：明确的小bug修复、配置调整
- **AI权限**：修改代码
- **改动限制**：≤ 20行，文件 ≤ 2个，逐次确认

### Level 3：增量开发（需评估报告+授权）
- **场景**：修复bug、加小功能
- **AI权限**：修改代码
- **改动限制**：默认 ≤ 50行，文件 ≤ 3个；可扩展至 ≤ 100行，文件 ≤ 4个（需说明理由）
- **要求**：改动前自动 git backup

---

## 改动红线（绝对不改）

除非用户明确授权，否则绝对不修改：

1. **数据库结构**
   - ORM模型文件（models.py）
   - 数据库迁移文件
   - 数据库连接配置

2. **认证鉴权**
   - 登录/注册逻辑
   - 权限控制代码
   - Token/密钥处理

3. **支付财务**
   - 支付接口
   - 财务计算逻辑
   - 订单处理核心

4. **核心业务**
   - 核心算法
   - 关键业务逻辑

---

## 评估流程

### /assess-project

在项目目录下执行，AI将：

1. 结构扫描 → 技术栈识别
2. 风险评估 → 核心业务识别
3. 输出项目评估报告

### 评估输出格式

```markdown
# 项目评估报告

## 基本信息
- 项目类型：[自研/二次开发/开源改造]
- 技术栈：[列出]
- 代码规模：[行数估算]

## 风险矩阵
| 区域 | 风险 | 说明 |
|------|------|------|
| xxx/ | 高 | ... |

## 推荐级别：Level 3

## 红线清单
1. models/user.py
2. auth/*.py
3. ...

## 下一步建议
...
```

## 开发流程

### /incremental-dev [任务]

已有项目的增量开发命令：

**改动前**：
1. 确认改动范围
2. 检查红线
3. 自动git backup

**改动中**：
- 默认每次≤50行，文件≤3个
- 可扩展至≤100行，文件≤4个（需说明理由）
- 涉及多文件先说明
- 遇红线立即停

**改动后**：
- 说明改动内容
- 提供验证方法
- 确认功能正常

## 快速回滚

```bash
# 自动备份
git tag "backup/before-$(date +%Y%m%d-%H%M%S)"

# 回滚
git checkout backup/before-XXX -- <file>
```

## 已有项目设计原则

**默认遵循**：
- 不重构无关文件
- 不"顺手优化"
- 不添加未要求的功能
- 不修改红线文件
- 不动认证鉴权
- 不碰支付财务

**允许情况**（需说明收益）：
- 改动范围内发现严重代码异味（如SQL注入、硬编码密钥）
- 与当前改动直接相关的代码可小幅优化（≤5行）
- 消除明显的重复代码

## 遇到问题

超出范围时：
```
[红灯] 任务需要改动 [红线/超出预算]
建议：/assess-project 先评估
或：缩小范围，只做核心改动
```
